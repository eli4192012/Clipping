# v5.28 · Local multimodal curation, first phase

This release adds a curation layer using existing speech review, sampled video frames, sound classification and genre presets. It can influence which existing moments are selected, and it exposes the supporting evidence. It does not add emotion inference, train a proprietary model, learn from channel analytics or establish improved audience retention.

## What changed

Project settings include **Use speech, visuals & sound to choose clips** and **Moments to review visually**, from 1 to 6 with a default of 3. The pass runs after existing editing/integrity checks and before coverage/overlap selection. All candidates receive retained-range sound evidence; the highest-priority eligible candidates receive three learned frame observations each. A cheap source scan records motion and camera changes. This is limited visual review of existing moments, not exhaustive visual discovery.

Speech remains authoritative. Exact-quote grounded opening/clarity/value/payoff ratings are reused when available; a missing rating stays unknown. Interview, Podcast, Sports, Music and Gaming presets weight supporting evidence differently. The combined estimate is shown with its available weight, and only small sound/visual adjustments affect the existing priority. Passed status, grounded review precedence, rejection flags, non-overlap and coverage rules remain ahead of that adjustment. A deterministic one-question interview check can reject a candidate; visual or acoustic cues cannot approve it.

**Speech, visuals & sound evidence** shows source frames/timestamps, signal estimates/weights, sound windows and possible reaction events, motion/camera-change counts, failures and downloadable JSON. For existing clips, **Advanced → Review this moment with speech, visuals & sound** reviews the actual final retained ranges and corrected final transcript. It does not apply an edit, create a new render or change posting copy. Viewing evidence does not run inference. Stale source/cut reports are hidden, and explicitly reviewing a report with missing frame files rebuilds those samples.

## Local components and provenance

- Existing local Whisper transcripts and the selected Qwen speech editor are reused. No retranscription was performed for the curation trials.
- The installed **Qwen3-VL 4B**, loaded through MLX-VLM, reviews one sampled frame at a time. Three samples are positioned at 10%, 50% and 90% of the retained timeline and mapped back through internal source gaps. Actual decoded timestamps must be inside a retained range. No new vision weights were downloaded. The smaller 2B model remains available for existing app features; this curation pass specifically uses 4B. See the [official Qwen3-VL model card](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct).
- Google's **YAMNet** provides 521 AudioSet sound classes from mono 16 kHz audio. The app keeps only complete 0.96-second model windows inside each retained source range, so a reaction from removed footage cannot bridge an edit. Audio is decoded in 30-second blocks, with source-time silence inserted for delayed audio. Sound labels and scores are uncertain model observations, not calibrated probabilities of a reaction or views. See the [official YAMNet documentation](https://github.com/tensorflow/models/blob/master/research/audioset/yamnet/README.md).
- YAMNet source and class map are vendored unchanged from TensorFlow Models commit `930a6f98f7debcc32ca7afbca4a176dbf9211e03`, retaining copyright headers and the full Apache 2.0 license. Official weights come from [Google's weight file](https://storage.googleapis.com/audioset/yamnet.h5); SHA-256 is `13c3308955bbfaef262f175ac9c40e47b134573a93984f009220dd7cc12a1744`, with a verified size of 15,296,092 bytes.
- `setup_sound.py` explicitly installs pinned TensorFlow 2.20.0 / tf-keras 2.20.0 dependencies in **.venv-audio**, verifies the downloaded weights and runs a local 521-class inference check before marking setup ready. `requirements-sound.lock.txt` records the successful separate environment. The main app environment and dependency files were not altered. Setup is completed on this Mac; a fresh clone needs this optional one-time command and the normal vision model setup.

Inference uses installed files with offline environment flags. Sound and vision workers share the existing serial model lock; app jobs share the existing heavy-job lock. The development Mac has 8 GiB RAM, and MLX retains its 3 GiB limit. There is no new paid API or account. The genre presets are explicit rules; no separate genre classifier or emotion model was installed.

The sports check was a manual full-source review window marked **passed=false**, not a fabricated approved highlight. Private trial logs, reports and sampled images are under `work/v528-validation/` and each project's `multimodal-curation/` cache; they are excluded from Git.

These times include fresh final-model frame review and report assembly, with sound/motion caches populated during earlier development attempts. They are **not fresh whole-source multimodal benchmarks**, whole-video processing estimates or proof of acceleration. No new exports were needed for these checks. The live saved-cut action reused existing sound/frame caches and took approximately 0.10 seconds to assemble its separate report; Streamlit navigation/job overhead is additional.

The initial 2B attempt sometimes copied the complete allowed-shot list instead of choosing one label. Invalid responses remained unavailable. A revised prompt produced valid but unreliable positive action/reaction labels on ordinary speaking frames. The final pass therefore uses the already installed 4B model, a concrete JSON example and conservative conflict checks. Manually inspected interview samples matched the broad seated-speaker/smile observations. However, a sports description at 28.19 seconds said a player held a red circular object when the sampled picture showed a foreground sideline marker. That relationship error was not caught automatically. It gave no action bonus and did not approve the draft, but demonstrates why observations still need review.

Completed final reports reopened with sound inference, motion scanning and vision workers patched to fail if called. Reopening took **0.0074s**, **0.0467s** and **0.0155s**, respectively, and invoked none of those operations. Cache identity includes source size/mtime, input transcript/candidates, retained ranges/final text, genre, visual model configuration and sound model/version. Per-source sound/motion and per-cut visual caches are independent. Failed reports retain visible diagnostics and can be retried explicitly; passive viewing does not retry.

## Tests and live controls

**330 tests passed** in the final full suite, in **213.751 seconds**. Twenty-one new tests cover preserving inputs/cuts/pass states and posting copy; cache reuse without inference; failed models/unknown signals; changed sources/cuts; one-question vetoes; source-gap frame/audio alignment; priority changes without bypassing integrity; genre routing; curation before selection with discovery reuse; passive UI behavior; missing-image recovery; real silent media; and a real delayed-audio fixture that verifies source-time padding. Test-suite duration includes existing rendering and UI checks; it is not an inference-speed measurement.

The existing saved turnover clip's Advanced button completed and displayed the three actual source images at **100.77s, 112.15s and 124.29s**, the 51 sound windows and local model name. ## Preservation and limits

The inventory covered **1,940 existing files** under data, exports and models. None were removed. Three existing metadata files changed size/mtime during the session: a finished-clip index and variant manifest in another existing project, and the inspected turnover project's UI settings, which gained the new curation fields. Every inventoried prior source, transcript, model weight, rendered export, caption correction, applied cut/style selection, posting draft and example-library record retained size/mtime. The seven supplied original MP4s also retained their SHA-256 hashes. New sound files and curation caches were added separately; media/model weights/environments and personal reports stay outside Git.

The UI release increments once to **v5.28**. The existing `modes.VERSION=10` analysis-cache version stays unchanged; enabled curation has its own tag and reports. Discovery/transcription caches are reused when their inputs match, and prior saved analyses remain available. Enabling this feature adds work, particularly frame inference, and the estimate is explicitly approximate. Progress reflects source decoding, completed frame reviews and pipeline milestones rather than constant speed.

This phase establishes local model integration, inspectable evidence, conservative priority changes, reuse and preservation. It does not establish better editorial choices, accurate sports descriptions, emotion understanding, retention gains or parity with a commercial curation system. It also does not fix the inaccurate hooks exposed by the v5.27 comparisons. Stronger visual coverage, sound calibration and human comparisons of actual selected clips are further work.
